# 关键决策记录

记下「为什么这样做」，方便以后回头理解或推翻。每条包含：背景、决定、代价。按时间顺序排列，时间均为 2026 年 11 月。

## 1. 文章类内容合并为一个集合，差异放进板块注册表

- **背景**：`blog` 与 `weekly` 原是两个 schema 完全相同的集合。新增一个板块要改 7 个文件；周报功能上线当天就因为漏改标签页导致构建失败。两套详情页代码有 84% 重复，同一个修复要改两遍。
- **决定**：合并为 `posts` 集合，一级子目录名即板块，URL 不变。板块的标题、每页条数、是否进首页、是否显示上一篇/下一篇、是否拉宽正文等，全部写在 `app/config/sections.ts`。详情页与列表页抽成共享组件，页面只做薄封装。
- **代价**：文章路径在集合内全局唯一，但页面只能展示自己板块下的文章，所以详情页多了一道「路径是否属于该板块」的判断，并有用例守着跨板块访问返回 404。

## 2. 质量门禁放在 CI 与部署流水线，不装 git 钩子

- **背景**：仓库原来没有任何 lint、类型检查、测试与 PR 流程。原计划在本地装提交前钩子。
- **决定**：只在 CI 和部署流水线里做检查。
- **代价**：本地提交不会被拦截，问题要等到推送后才暴露。原因很具体：文章机器人是在 launchd 的默认环境（没有 node）里执行 `git commit` 的，任何依赖 node 的钩子都会直接拒绝它的提交。

## 3. 机器人不改为开 PR，改为「校验通过才部署」

- **背景**：机器人直接向 `source` 推送，等于直推生产。
- **决定**：部署流水线拆成「先复用 CI 做全部检查」和「再部署」两步；机器人保持直推，但产出的内容必须先过检查才能上线。另外给两个机器人脚本做了加固：发布前先快进拉取、确认停在 `source` 分支、发布失败时发通知。
- **代价**：不合规范的内容会让当天的部署停在上一个可用版本，需要人工处理。

## 4. Node 固定为 26，内容数据库改用内置 SQLite

- **背景**：`engines` 写的是 `>=22`，CI 用 22、本机用 26，本地验证过的构建与线上的不是同一环境；项目还带着一个需要编译的原生模块。
- **决定**：`.nvmrc` 固定 26，CI 读同一个文件；改用 Node 内置的 `node:sqlite`，移除 `better-sqlite3`。
- **代价**：本机默认 Node 版本低于 26 时需要先 `nvm use`。顺带发现并修掉了一个真实问题：项目里显式声明的 `vue-router ^4` 与升级后的 Nuxt（需要 5）并存，依赖树里同时存在两份路由器。

## 5. 背景动画改为原生 Canvas 实现

- **背景**：文章页的流场背景依赖 p5i，这个库打包后超过 1MB，而且被全站每个页面预取；动画不响应系统的「减少动态效果」。
- **更正**：审查时给出的「每帧 50–80ms」是在调试器附加的浏览器里测得的，被放大了约 5–8 倍。不带调试器实测：每帧约 10ms，动画运行期间主线程约 70–95% 的时间是忙的——「持续占用主线程」的定性结论成立，量级不成立。
- **决定**：用原生 Canvas 重写（噪声函数有独立参照值校验），限 30 帧、像素比封顶 2，减少动效与页面不可见时停止。
- **代价**：视觉效果与原先并非逐像素相同，只做了像素统计层面的对比（墨量与有墨迹的像素占比差异在 2% 以内）。实测改后文章页的脚本 CPU 降为原来的约十分之一。

## 6. 列表在数据层分页，去掉列表页的标签筛选条

- **背景**：列表页一次渲染全部文章，页面数据还带着每篇文章的正文。
- **决定**：列表查询只取卡片需要的字段，并在数据层分页（每页 20 条，旧文章在 `/<板块>/page/<页码>`）。标签页一次取回全部摘要，在浏览器里按 `?page=` 分页。
- **代价（可见的界面变化）**：列表页顶部原有的标签筛选条被去掉了——筛选结果跨页，与分页天然冲突；当时全站只有一个标签，筛选条并没有实际作用。卡片上的标签仍然可以点进标签页。标签页的数据会随文章数缓慢增长（每篇约 400 字节）。

## 7. frontmatter 的校验交给内容校验脚本

- **背景**：原计划「收紧 zod schema，让格式错误在构建时失败」。
- **发现**：这个版本的 Nuxt Content 只用 schema 生成类型，不在构建时校验 frontmatter。日期写成 `2026/01/02` 的文章照常被预渲染。
- **决定**：新增内容校验脚本，检查必填字段、日期格式、图片路径与卡片链接，并入 `npm test` 与 CI。
- **代价**：schema 与校验规则是两处定义，改字段时要一起改（CONTRIBUTING 的改动清单里列了）。

## 8. 被截断的描述在源头修正，站点不做渲染时清理

- **背景**：机器人生成描述时按 78 个字硬截，10 篇文章的描述都停在半句话上，有一篇甚至把 `145B` 这个数字劈开了。
- **决定**：生成器改为按句读截断；存量的 10 篇用归档的完整导语重新生成。站点代码不做启发式清理。
- **代价**：以后若出现别的来源的截断描述，站点不会兜底，只有内容校验脚本会提醒。不做渲染时清理的原因是周报的描述是结构化文本，本身没有句末标点，启发式规则会切掉它的后半截。

## 9. 站内地址一律带尾斜杠

- **背景**：GitHub Pages 把不带尾斜杠的地址 301 到带尾斜杠的地址。
- **决定**：canonical 与站点地图统一使用带尾斜杠的形式，指向最终地址。
- **代价**：换成不补尾斜杠的托管方式时需要改地址工具函数，有用例会拦住不一致。

## 10. 第三方 Action 固定到提交哈希；Pages 部署改造延后

- **背景**：工作流用可变的 `@v4` 标签引用 Action，而部署流水线持有仓库的写权限。
- **决定**：全部固定到提交哈希并注明版本，由 Dependabot 提升级 PR；新增一条守卫测试。
- **延后的事项**：把部署方式改为 GitHub Actions 直接发布产物（`upload-pages-artifact` + `deploy-pages`），可以去掉 `master` 这个产物分支。这需要同时切换仓库的 Pages 来源设置，属于会影响线上的操作，应当在本轮改动稳定运行之后单独进行。

## 11. 两处「不改」是刻意的

- `DailyCard` 只移动位置、不改名；Nuxt 的 `pathPrefix: false` 保持不变。原因相同：Markdown 里的 `::daily-card` 标签名由组件文件名与命名方式决定，机器人每天产出的内容都依赖它。
- 仓库没有添加 LICENSE：许可证是作者本人的决定。

## 12. 沿用的经验

- **Nuxt 的 composable 必须在第一个 `await` 之前调用**，否则运行时报 `NUXT_E1001`。
- **端到端用例里，断言位置或动画之前要先等状态停稳**，并且做一次反向验证（去掉修复应当失败）。锚点跳转的用例先后写错三次，都是靠反向验证才发现的。
